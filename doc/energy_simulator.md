# Energy Simulator

The goal of the Energy Simulator is to emulate the operation (simplified) of the boat energy system to feed the various energy devices (Battery, MPPT, CHargers) with simulated values in order to test the Navigation Server Energy Management System.

## Architecture

The simulator includes a back_end process generating a set of simulated values using four sources:
- Parameters and data from the EnergyService process
- Static parameters from configuration files
- User inputs data
- Calculated values

These input values are given by the front_end Web UI communicating to the back end process that is acting as web_server.

The calculated simulated values are then sent over to the EnergyService process using a gRPC service: EnergySimulator.
The EnergySimulator service shall be added to the EnergyService process and will serve simulated values to the EnergyService process.
The devices (Battery, MPPT, Chargers) in the Energy process shall be configured in simulation mode.

## Simulator initialization

The simulator will get initial values from:
- The configuration file (YamL)
- By querying the agent to get the EnergySimulator service address
- Then from the EnergyService service itself, it will get the configuration from each device and thus the configuration to be used for the simulation.
- User inputs for variable data

## The EnergySimulator service

This service will be responsible for injecting simulated values to the EnergyService process. It must be added and will receive simulated values and parameter changes from the SimulationServer (a Web server that is a client from the EnergySimulator service).
When receiving the simulated values and parameter changes, the EnergySimulator service will translate these changes into dictionaries compatible with those generated by the VE direct interface. and call the publish method of the corresponding device.

The protobuf for EnergySimulator service is defined in the file `energy_simulator.proto`.

## The EnergySimulator server

This is a process having the same structure as any other process in the project (the top module is always 'server_main.py'). It is also a Web server, so can also reuse the wep_top_server.py module with some adaptations.

Simulation inputs will be received from the Web UI and will work in cycles in which it will:
- Evaluate the simulation inputs
- compute all main system values
- Publish the simulated values to the EnergyService process via gRPC

Cycles periods can be tuned but shall be in the range of 1 to 10 seconds.

Before starting the cycles, initial conditions can be set with the UI.

The values and algorithms used for each device are defined in the following sections.

### Battery simulation

Initial condition:
- State Of Charge: percentage of the battery total capacity actually available. It cannot be changed during the simulation.

Static parameters specific to simulation:
- Voltage for 100% SoC: voltage of the battery when it is fully charged.
- Voltage for 0% SoC: voltage of the battery when it is fully discharged.
- Charging efficiency: percentage of the energy that is actually stored in the battery when charging.

Inputs to simulation algorithm:
- voltage: theoretical voltage of the battery based on SoC assuming linear variation between 0 and 100% SoC.

Inputs from the simulation algorithm:
- Current: current flowing through the battery. This will be used to recompute the SoC for the next cycle based on the energy variation.

Output to the EnergyService process via gRPC:
- Voltage: voltage of the battery. It shall be the global system voltage
- Current: current flowing through the battery.
- Power: power flowing through the battery.
- State Of Charge: percentage of the battery total capacity actually available.

### Consumption simulation

The consumption (in Watts) is one key input to the simulation algorithm. Two types of input are possible:
- Constant consumption: the value is set on the UI, and a slider can be used to adjust it.
- Variable consumption: The consumption will randomly vary between a minimum and a maximum value that are set in the UI.The number of cycles between new radom values is adjustable.

Static parameters for the simulation:
- Maximum consumption in W

Inputs to simulation algorithm:
- consumption power for the cycle

### MPPT simulation

Static parameters specific to simulation:
- Panel voltage for maximum production (maximum production can be retrieved from the MPPT service)
- Panel voltage for minimum production
- Max output voltage corresponding to maximum production
- Voltage factor: Volt decrease per W of missed production to compute the theoretical output voltage
- Output power factor: Power decrease factor based on delta voltage between theoretical output voltage and system voltage.
- Minimum voltage delta: Minimum difference between panel voltage and output voltage to produce output

Inputs to MPPT values calculation:
- panel voltage from UI between min and max.

Inputs to simulation algorithm:
- Output current: current out of the MPPT
- Output power: power out of the MPPT
- Output voltage: voltage out of the MPPT

Inputs from the simulation algorithm:
- system voltage

Output to the EnergyService process via gRPC:
- Panel voltage
- Panel power
- output current
- output voltage (= to system voltage)

#### MPPT simulation algorithm

We start from the panel_voltage (external UI input). Then:
1) If panel_voltage < system_voltage + min_voltage_delta => MPPT is off, we stop here. Output voltage = system_voltage, output_current=0
2) We compute the theoretical production (W)
3) We compute the output voltage using voltage_factor. If output_voltage < system_voltage, we stop here. Output voltage = system_voltage, output_current=0
4) We compute the output current/power using power_factor

### DC-DC Charger simulation

Static parameters specific to simulation:
- Charger efficiency

Inputs to simulation algorithm:
- input current: from UI
- input voltage: from UI
- output voltage: from UI. Shall >= system voltage
- output current: computed using the charger efficiency

Output to the EnergyService process via gRPC:
- output current
- output voltage (= to system voltage)
- input current
- input voltage

### Global energy equilibrium and system voltage calculation

#### System voltage

The system voltage == Battery voltage if no current source (device) is on

If there are one or more current sources, the system voltage is the maximum across all current sources and the battery.

#### Current/Power equilibrium

Case 1: No current source (device) is on
- Battery draw current = Consumption current


Case 2: One or more current sources (devices) are on and sum of all current sources (devices) current <= consumption current
- Battery current = Consumption current - sum of all current sources (devices) current

Case 3: Production current > consumption current
- Battery current = sum of all current sources (devices) current - production current - Production current

The case where the production current exceeds the maximum charge current for the Battery is not supported.

### Computation and communication cycle

1) From the current conditions resulting from the initial state or previous cycle, each source is computing its output values.
2) The global energy equilibrium and system voltage are calculated.
3) messages with simulated values are sent to the EnergyService process via gRPC.
4) And the next cycle starts all over again

### Device parameters

Coming from the UI (or configuration file) some parameters can be sent to populate the VE direct values dictionary. This can be used to specify some specific conditions or static parameters.

## Web UI

The Web UI allows entering all dynamic parameters. There shall be one global box to start/stop the simulation, set the cycle period.

Then one box per device for the device-specific parameters. A button (slide button) can put the device on/off, except for the battery.
Each box can allow the input of one or more parameters that are key/value pairs.
